## 1. Чанарын сценариуд (6 хэсэгтэй формат)

### 1.1 Performance сценарио — /cart/add хариу хугацаа

| Хэсэг | Агуулга |
|---|---|
| Тойм | /cart/add endpoint хэвийн ачааллын үед хэр хурдан хариу өгөх ёстойг тодорхойлно. |
| Системийн төлөв | Систем идэвхтэй, ямар нэгэн эвдрэл байхгүй тогтвортой ажиллагаатай үе. |
| Орчны төлөв | Хэвийн ачаалал: 20 VU, 1 минутын турш, localhost сервер. |
| Гадаад өдөөлт | Хэрэглэгч дэлгүүрийн сагсанд бараа нэмэх хүсэлт (POST /cart/add) илгээнэ. |
| Шаардлагатай хариу | Сервер хүсэлтийг богино хугацаанд, алдаагүй (200 OK) боловсруулж хариу буцаана. |
| Хэмжүүр | Хариу хугацааны 95-р перцентиль (p95) < 200 мс байх. |

### 1.2 Reliability сценарио — /pay эвдрэлийн давтамж

| Хэсэг | Агуулга |
|---|---|
| Тойм | /pay endpoint төлбөрийн хүсэлтийг боловсруулахдаа хэр олон удаа алдаа (500) буцааж байгааг хэмжинэ. |
| Системийн төлөв | Систем ажиллаж байгаа, гэхдээ backend заримдаа хугацаа алдаж эвдэрдэг. |
| Орчны төлөв | Хэвийн ачаалал: 20 VU, 1 минутын турш, localhost сервер. |
| Гадаад өдөөлт | Хэрэглэгч захиалгаа төлөх хүсэлт (POST /pay) илгээнэ. |
| Шаардлагатай хариу | Сервер ихэнх тохиолдолд амжилттай (paid: true) хариу буцаах ёстой. |
| Хэмжүүр | POFOD / error rate < 8%. |

### 1.3 Availability сценарио — сервер унаж, дахин асахад

| Хэсэг | Агуулга |
|---|---|
| Тойм | Сервер гэнэт зогсоод 10 секундийн дараа дахин ажилласан үед хүртээмж хэрхэн өөрчлөгдөхийг хэмжинэ. |
| Системийн төлөв | Систем эхлээд хэвийн ажиллаж байгаа, дараа нь гэнэт зогсоод (crash), 10 секундийн дараа дахин асдаг. |
| Орчны төлөв | 10 VU ачаалалтай, 2 минутын турш; тестийн явцад 10 секунд серверийг зориудаар унагаана. |
| Гадаад өдөөлт | Сервер процесс гэнэт зогссон эвдрэл (crash) — хэрэглэгчийн хүсэлтүүд тасралтгүй ирсээр байна. |
| Шаардлагатай хариу | Систем аль болох богино хугацаанд сэргэж, дараагийн хүсэлтүүдэд амжилттай хариу буцаах ёстой. |
| Хэмжүүр | Нийт хугацааны availability >= 90%; сэргэх хугацаа бүртгэгдэнэ. |

## 2. SLO хүснэгт

| Сценарио | SLI | Босго | Цонх / нөхцөл |
|---|---|---|---|
| Performance | /cart/add latency (p95) | p95 < 200 мс | 20 VU, 1 мин |
| Reliability | /pay error rate | rate < 0.08 (8%) | 1 мин, 20 VU |
| Availability | бүх хүсэлтийн амжилтын хувь (checks) | rate > 0.90 (90%) | 2 мин, 10с зогсолт орсон |
| (нэмэлт) Performance | /report latency (p95) | p95 < 450 мс | 20 VU, 1 мин |

Босго сонгосон үндэслэл: Сервер /pay дээр санаатайгаар ~5% алдаа гаргадаг тул 8% threshold нь бодит нөхцөлд тохирсон, хэт хатуу биш, хэт сул ч биш босго болно.

Error budget (цагаар): Availability SLO 2 минутын (120 секунд) цонхонд >=90% гэдэг нь 10% буюу 12 секундийн "эвдрэх эрх" (error budget) байна.
